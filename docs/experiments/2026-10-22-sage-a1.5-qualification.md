# Sage-A1.5 MLX qualification and model selection

Experiment period: 2026-10-22 through 2026-10-23.
Outcome: passed scoped checks for both Sage quantizations on one physical host.
Disposition: incorporated into Geer 0.4.0; the two-family chooser superseded
the Sage trial and single-default preparations.

## Question and scope

Could Sage-A1.5 improve Geer's model selection while retaining native images,
repository tools, retrieval, cancellation and resumable T3/Pi sessions? The
work covered conversion, bounded inference, real T3 integration and release
verification. Upstream benchmark reports supplied quality proxies; Geer did
not reproduce them or establish their preservation after quantization.

## Results and corrections

Initial API and ACP checks passed, but T3 failed before inference because its
injected MCP server used stdio and Geer accepted only HTTP. Native image
support and stdio compatibility repairs enabled the real T3 continuation.
Sage corrected an import error in its generated tests. A trial wrapper then
interrupted the turn with an incorrect whole-turn deadline; correcting that
wrapper allowed the saved session to finish without resetting the fixture.
After the Pi 1.4 upgrade, a tool-name normalization change also required a
test-fixture correction, rather than a production transport workaround.

The 6-bit candidate passed native image interpretation, repository reads,
edits and tests, actual Semble retrieval and tool-result continuation. Its first
larger uncached coding task still failed: summary counts ignored filters.
Eleven of twelve external-grader methods passed, two local tests failed, and
the browser loop remained incomplete when the 45-minute allowance expired.
Repeated large prefills affected wall time but did not excuse the incorrect result.

An authorized follow-up enabled normal isolated product caches, 16 GB SSD and
8 GB hot cache. Sage corrected its patch and its own test assumptions. All
27 local tests and all twelve frozen external-grader methods passed; the
controller independently reran checks without repairing the patch. Sage then
completed a browser screenshot/action/verification loop for import, filtering
and persistence. Controller assistance supplied the browser-panel prerequisite,
tool and tab corrections, and action reminders. This was an assisted browser
pass; general desktop control is unqualified.

The mixed 4/8-bit candidate passed its own native read/edit/test checks and
three independently rerun tests. Fresh synthetic image input passed without
exposing its expected fields through HTML. Actual Semble retrieval and a
native screenshot/click/screenshot canary also passed, with controller
reminders during the checks. These results do not inherit acceptance from
the 6-bit run.

Both quantizations subsequently passed native T3 cancellation during active
generation with partial assistant text. The old Pi process exited; a fresh Pi
process resumed the same JSONL, preserved its prior prefix and recalled
withheld session or image details without receiving them again. Six-bit checks
also verified skill routing and rejection of interactive use below Full access.
Skill routing passed despite a prose-style miss in the resulting rewrite.

## Context and performance limits

Cold-prefix 32K probes used 30,688/30,700 prompt tokens and 2,048 generated
tokens, with model loading excluded from TTFT. Two-run means for Sage 6-bit
and Ornith 6-bit were both about 24.4 seconds TTFT and 79.8 decode tokens/s.
Separate isolated mixed probes measured 22.64/24.02 seconds and 81.49/81.52
tokens/s, with no cached prompt tokens. Both Sage profiles met the agreed
host-specific floor of at most 60 seconds fresh-32K TTFT and at least 20
decode tokens/s. Concurrent mixed timings from an earlier run were excluded.

Cached native follow-up turns are separate observations. The six-bit task's
first 81,046-token prompt took about 99 seconds; subsequent cached tool turns
mostly took 3.7 to 8.6 seconds. That difference supplies no new matched speed score.

Sage 6-bit and Ornith 6-bit passed one uncached 64K capacity probe each,
using 63,445 prompt and 2,048 generated tokens. Useful-context credit remained
at 32K: neither padding nor larger T3 preludes established a task benefit from
retaining extra material. No useful 64K tier, 128K/256K ceiling or smaller Mac
was qualified. Sampled Sage runs showed no swap or sustained critical memory
pressure; allocator peaks are distinct from process RSS and total system use.

## Decision and revisit conditions

The initial screen retained Ornith as preferred. A subsequent reassessment
applied the accepted upstream quality proxies to the reviewed 50% reported
quality, 30% useful context and 20% speed comparison, which favored Sage on
this host. Native follow-up then closed the remaining scoped capability gates.
Reported instruction-following and search gains carried more weight than the
small coding-score differences; Ornith retained an advantage on DeepResearchBench
II. Published harnesses and reasoning settings differed from these local
non-thinking runs. No upstream score is a measured result for either quantization.

Geer 0.4.0 shipped both families with Sage recommended at initial setup,
retained confirmed choices and one active model, and kept oMLX. Separate native
checks covered both Ornith variants. The signed, notarized release included
frozen discovery checks for all four variants. Native wizard mouse/keyboard
interaction remained unverified after computer-control failures; detached
renders and controller tests did not close that gap.

Revisit an exact profile when weights, quantization, tokenizer/image handling,
runtime, Pi or T3 contracts change. Record the tested runtime archive hash in
future trials. Qualify each smaller physical Mac separately with images,
32K total context, tools, retrieval, memory and latency checks. Require a task
that benefits from retained material before promoting useful context above
32K, and separate browser autonomy or desktop-action trials before expanding
computer-use claims. Technical success makes no additional licensing finding.

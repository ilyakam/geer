# Qwen3.8 MTP exactness and proposal quantization

Experiment period: 2026-08-15 through 2026-08-16.
Outcome: throughput improved, but the broader exact-output gate failed.
Disposition: automatic MTP rejected for the tested configurations.

## Question and scope

Could native multi-token prediction accelerate the same Qwen artifact while
preserving exact greedy output, including stop boundaries? A follow-up also
checked whether quantizing only the proposal head preserved target weights.

## Configuration

- Target: the [6-bit artifact](2026-08-15-qwen3.8-mlx.md) at
  revision `26e46ace34317b8e04377e7a65615cedb0475897`.
- Host: Apple M4 Max, 128 GB unified memory; greedy sampling, cache-equivalent
  MTP-off/on comparisons. The original 690-token comparison disabled cache.
- Runtimes: pinned oMLX 0.5.3 revision
  `31d07a7fdbbb499d4520188fb7e8f7bdbfe4c770` and a 0.6.0 candidate.
  The candidate's exact revision was not retained with the comparison table.
- Follow-up: four bounded workloads, including a low-redundancy stop-boundary
  case; MTP depths 1, 2, and 3.

## Result

The initial 690-token workload produced identical output: median generation
took 38.107 seconds with MTP off and 16.923 seconds on. A longer retrieval
workload showed almost no total-latency improvement, and a separate warm
install calibration selected off. The first speedup was workload-dependent.

The later four-workload gate superseded that initial exactness result:

| Runtime | Serial median tokens/s | Depth-3 median tokens/s | Exact cases |
| --- | ---: | ---: | ---: |
| oMLX 0.5.3 | 17.968 | 42.642 | 3/4 |
| oMLX 0.6.0 candidate | 18.041 | 43.915 | 3/4 |

The failing stop-boundary workload generated 1,094 tokens serially and 1,079
with MTP. Depths 1 and 2 also diverged. The throughput benefit therefore did
not satisfy the required exact-output behavior on either runtime.

A local 4-bit proposal-head candidate preserved the canonical bytes of all
2,176 target tensors, totaling 25,797,171,680 bytes. Model residency fell from
about 25.27 to 24.72 GiB, and median depth-3 throughput was 43.863 tokens/s.
It reproduced the stop-boundary failure. No immutable published revision was
recorded for that candidate.

## Decision and revisit condition

Keep automatic MTP off for these tested configurations. Proposal-head
quantization reduced memory but did not repair exactness. Revisit after a
runtime change that addresses the observed divergence; require the same
artifact, equivalent cache state, exact greedy output and stopping behavior,
and multiple workloads before considering performance. A proposal-only
change must also preserve every target tensor byte for byte.

This is historical experimental evidence. Geer 0.3.0's Pi/Ornith path does
not acquire Qwen or MTP support from this record.
